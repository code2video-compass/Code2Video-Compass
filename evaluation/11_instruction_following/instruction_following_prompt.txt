# Evaluation — Fine-grained QA

Evaluate every QA item provided, independently and in input order. Do not add, remove, or rewrite items.

## Judgment Rules

**Please grade strictly based on directly observable evidence.**

- Evaluate only the supplied QA questions. Use the creative brief to interpret the questions and their references, including conditions that a question explicitly asks you to assess from the brief. Do not introduce additional scoring conditions beyond what each question requires.
- Do not default to Yes because the video looks good, follows the general theme, or satisfies most of a question. Base each answer on directly observable evidence that satisfies the question's logical condition.

- **Yes**: clear and directly observable evidence in the video confirms that the requirement is satisfied.
- **No**: the requirement is violated, incorrect, missing, or cannot be verified from the submitted video. This is a binary checklist; do not use a third answer such as `Unclear`.
- A Yes requires the question's complete logical condition to be satisfied, respecting conjunctions, alternatives, negations, and quantifiers exactly as stated. Partial satisfaction of a required conjunction is No. For an inclusive alternative (A or B), either alternative suffices; require exactly one only when the question states this explicitly.
- Verify requested text, states, and actions from the video itself, not from the brief or overall impression. A static endpoint does not establish the requested motion or transformation.
- Success on one requirement must not compensate for failure on another. Temporal and causal questions require both events and their visible relationship; an absent prerequisite cannot support Yes. Before finalizing, reconcile answers with observed evidence and do not assume events that your own assessment identifies as absent.
- For text, numbers, quantities, spatial relations, ordering, and temporal requirements, verify the exact requested content rather than approximate similarity.
- For a specified visual style, judge the actual rendering; matching the subject or motif alone is insufficient.
- Return each question's integer number in `question`, in input order. Do not repeat the question text or add identifiers or taxonomy labels.
- QA is a binary evaluation record: return only the question number and `Yes`/`No`. Do not add a reason or explanation to any checklist answer.
- Do not calculate QA averages, AllPass, or an overall score. These will be computed externally.

---

# Output Format

Return valid JSON only. Do not output Markdown or additional text. The `qa` array must contain exactly one result for each input checklist item, in the same order; its length is variable. Do not add results for absent sub-dimensions.

{
  "qa": [
    {
      "question": 1,
      "answer": "Yes"
    }
  ]
}

For each QA result, use exactly `question` (its integer number) and `answer` (`Yes` or `No`). Do not include a reason, explanation, or `null` field for checklist answers.
